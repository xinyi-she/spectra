# 设计说明与实测记录

这份文档记录 SPECTRA 的谱面生成是怎么做的、以及**每一条规则背后的数字**。
所有结论都来自可复现的脚本（见文末「工具」），改参数前后能直接对拍。

> 面向使用者的说明在 [README](../README.md)。

## 谱面是怎么「AI 生成」的

`js/analyzer.js` + `js/chart.js`，不调用外部模型，纯信号处理 + 规则编排：

1. **STFT**：单声道 → 汉宁窗 FFT（44.1/48k 下 2048 点，hop ≈ 23ms）
2. **多频段谱通量**：bass / low / mid / high / air 五个频段分别做正向差分，各频段按 p97 归一后加权求和 → 击打强度曲线
3. **峰值拾取**：自适应阈值（局部均值 ×1.18）+ 局部极大 + 55ms 最小间隔 → 音符候选点，并标注频段特征（kick / snare / hat）
4. **BPM**：自相关做粗估 → 用「相位相干」精修（这一步很关键，129.3 → 130.0 的偏差会让整首歌漂 2 拍）→ 全拍搜索确定拍点相位 → 最小二乘拟合整曲网格
5. **吸附到网格**：原始 onset 相对拍点有 ±20ms 抖动（实测平均 22.6ms 偏差），直接排谱会显得「松 / 慢半拍」。所以先按 1/4（EASY/NORMAL）或 1/8（HARD）拍吸附、同格只留最强音。吸附后偏差降到 7.8ms，音符 100% 落在网格上
6. **强度曲线 → 密度**：按小节统计 RMS（响度）并平滑归一化成 0..1，混入该小节的击打点数量；
   每小节的目标密度 = 在该难度的「安静 NPS」和「高潮 NPS」之间插值 —— 主歌留白、副歌加密，密度和响度的相关系数实测 0.77~0.96
7. **基频检测**：每个 onset 取出 58ms 窗口做 YIN，得到音高与可信度（见下一节）
8. **谱面编排**：先按小节目标密度定出完整时间轴（选音 + 补连打），再统一排键位。
   键位不是随机游走，而是「**有旋律就跟着旋律，没旋律就套语汇**」：
   - 这一段有 60% 以上的音能测出可信音高 → **音高步进**（±1 格，本身就是 roll 形态）
   - 否则按节奏型套语汇：等间隔连打（1/8 或更密）→ roll（0123 / 3210）或 trill（两键交替）
   - 零散音 / 弱拍 → 加权跳，权重里综合了 5 条手感规则
   - 只有**强拍且足够炸**的位置才给双押，且按舒适度选第二键（外外 > 外内 > 内内 1-2）
9. **五条手感规则**（每条都对应一个具体的「难打」原因）：
   - **同键连打**（jack）重罚。唯一的例外是「音高完全相同」—— 那是音乐上真正的重复音，
     允许写成 jack，概率按难度给（EASY 0.1 / NORMAL 0.45 / HARD 0.9）
   - **交替加分**：上上个键正好是当前候选时给高权重，天然生成 trill（4K 里最舒服的形态）
   - **手平衡**：近期哪只手用得少就往哪边偏
   - **锚点抑制**：最近 8 个音里某根键出现过多就压权重
   - **大跳降权**：相邻移动最顺手，跨 3 个键的跳按难度打折
10. **长条**：只写在「接得住」的位置 —— 同轨后面留出呼吸、头落在 1/2 拍网格、
    长度由声音延续决定（见下方「长条：为什么不能连续」）
11. **开场缓冲**：谱面第一颗音强制落在 **3.4 秒之后、且压在小节线上**（128 BPM 下是第 3 小节）。
    之前只挡了 0.8 秒，一上来就有音的曲子会「一开播就开打」，完全没有准备时间；
    游戏端再兜一层：万一第一颗音还是太近，就先静音等够 3.4 秒（`audio.play(from, delay)`），
    这期间谱面时间是负的，倒计时照走
12. **收尾**：重音处生成特殊音符，最后用 1 秒滑动窗口限制 NPS（3.6 / 6.2 / 9.6）保证可打

### 旋律：从混音里测出音高

`js/pitch.js`，YIN 算法。难点不在算法本身，而在「复音混音里到底该听谁」：

1. **降采样到 12kHz**（先做抗混叠），搜索 90~1100Hz —— 覆盖人声、吉他、主奏
2. **先滤掉贝斯**：高通 170Hz ×2 + 低通 1600Hz。这一步是必须的 ——
   110Hz 与 220Hz 的**共同周期是 110Hz**，YIN 会给出一个「低八度」的答案，
   实测不做滤波时整首歌的音高全部低 12~24 个半音
3. **窗口从 onset +16ms 开始**：起音瞬态没有稳定周期，会把估计拉偏
4. **不做八度校正**：YIN 的规则是「取第一个足够低的谷」，2T / 3T 同样是合法周期，
   越往后越容易落到低八度。曾经加过「2 倍周期也合格就取 2 倍」，实测把整段旋律压低八度，已删
5. **稳定性闸门**：复音里 YIN 会在贝斯 / 人声 / 吉他之间来回跳，实测相邻两音的
   音高差常在 7~11 个半音 —— 那是换了声部，不是旋律。所以只保留「附近还有音高相近的音」
   的检测结果，孤立的跳变当成不可信
6. **3 点中值滤波**：削掉残留的单点尖峰，真实的大跳保留

**精度实测**（`node tools/test_pitch.mjs`）：合成的 12 音旋律，即使叠上底鼓、军鼓、
低频贝斯和高次泛音，也是 12/12 全部检出，**中位误差 1 音分、全部在 25 音分内**；
白噪声的可信度 0.11（门槛 0.5），打击乐能被正确排除。

真实歌曲的音高覆盖率 68~77%（《十重告别》76.6%，中位 217Hz ≈ A3），
测出的音高 100% 落在人声/主奏的合理区间。

### 音高 → 键位

拿到音高之后要回答一个问题：**4 个键怎么表达一条旋律？**

- **走向**：音高上升 → 键位右移，下降 → 左移；幅度按音程大小给 1~2 格
- **边界环绕而不是反弹**：4K 里 3→0 本来就被读作「继续上行」（roll 就是这么走的）。
  早期版本用反弹，结果旋律一上行键位反而左移，跟随率只有 50%
- **同一个音** → 允许落在同一个键上（真 jack），但只连两个
- **绝对音高**：偏高的音往外侧（0 / 3）偏，偏低的往内侧（1 / 2）偏 —— 对应「高音走外侧」
- **补音**：16 分补出来的音没有音高，按前后可信音高做**线性插值**（当作经过音），
  否则连打里「有音高」和「没音高」会交替出现，旋律线被切碎

实测「旋律跟随率」（相邻两音的音高变化方向与键位移动方向一致的比例）：
《十重告别》HARD **68%**、NORMAL 60%；《world.execute(me)》HARD 60%、NORMAL 61%。
随机分配的理论值约 50%。

### 节奏先验：从真实谱面蒸馏

前几轮的规则都是人手调的，难免主观。这一轮换成"先量真实谱面，再照着改"：

**语料**：osu!mania 4K 共 **160 张谱面、479,479 个音符**（osu.direct 公共镜像，
只下载 `.osu` 文本，每个约 50KB；只做聚合统计，**不包含任何原谱内容，也不重新分发**）。
抓取见 `tools/fetch_charts.py` / `tools/fetch_charts.mjs`，统计见 `tools/distill.mjs`，
产出的常量在 `js/chart-priors.js`。

量出来的几条关键事实：

| 事实 | 数据 |
| --- | --- |
| 相邻两个音的时值 | **52% 是 1/4 拍**，6% 是 1/8 拍，7% 是附点（3/16），其余 34% 更长 |
| 音符落在拍内什么位置 | 正拍 30%、半拍 26%、1/4 拍位 15%、3/4 拍位 16%，其余位置合计不到 13% |
| 双押以上占多少 | **40%**（双 29.7%、三 7.3%、四 3.0%） |
| 双押落在哪 | 正拍 **49%**、半拍 28%、3/4 拍 10%、1/4 拍 9% |
| 同键连打 | 快速（<1/4 拍）只有 2.2%，慢速 9.9% |
| 相邻小节节奏型完全相同 | **20%**（重音也计入节奏型；只看"有没有音"是 39%） |

对照自己的输出，差距非常明显：

| 指标 | 真实谱面 | 改前（HARD） | 改后（HARD） |
| --- | --- | --- | --- |
| 双押以上占比 | 43.1% | **3.9%** | 49.7% |
| 正拍音符占比 | 32.8% | 30.9% | 43.5% |
| 相邻小节节奏型相同 | 20.0% | **1.9%** | 12.5% |
| 1/4 拍间隔 | 51.9% | 79.4% | 39.8% |

**改前三宗罪**：几乎没有双押（所以没有重音、没有"顿"的感觉）、节奏型每小节都不一样
（所以没有记忆点）、音符均匀铺满十六分网格（像机器在数拍）。

于是改了三处：

1. **双押位置按真实分布撒**：正拍 1.63 倍权重、半拍 1.08、1/4 与 3/4 拍约 0.6、
   非十六分网格 0.2。这样重音压在正拍和半拍上，才有"点头"的支点。
2. **节奏动机 = 短语内的音频共识骨架**：把 4 个小节对应槽位的击打强度平均，
   最强的那 N 格就是这一句的节奏骨架；4 小节复用同一条骨架，末小节翻转两格做变奏。
   动机不是随机抽的 —— 随机抽会和音频对不上，反而更散。
3. **补音按骨架补满**：骨架上的格子只要"有一点声音"就补上（谱师写踩镲也是这么做的），
   而不是"够响才写、写满为止"。骨架就是密度上限，不再往骨架外撒音。

双押会把音符数翻倍，所以密度目标相应下调（HARD 9.9 → 7.0 nps），
最终 HARD 仍是 Lv12 / 7.14 nps，和改前同级。

### 段落结构与一致性

谱面不能每小节都换花样，否则打起来"没有记忆点"。所以先做结构规划：

1. **分档**：按每小节能量分「安静 / 正常 / 高潮」三档，连续同档的小节组成一个段落
2. **主题**：每个档位准备两套「乐句主题」（roll 的方向与起始键、trill 的键对）
3. **复用**：真正的重复段落**共用第一段的键位表**
4. **呼应**：段内后半用变体（roll 反向 / trill 换手），避免整段像复制粘贴
5. **曲线**：句内密度轻微递增（0.9 → 1.1），极安静的小节直接留白，形成 build-up 与 break

**这里有个修正**：早期版本是「同档位就照抄」，把能量相近的段落一律当成同一段音乐。
引入音高之后可以直接验证这个假设 —— 实测同档位段落的**平均音高差有 5~9 个半音**，
它们根本不是同一段音乐，抄出来的键位与旋律无关。所以现在照抄前要过一道**音高闸门**：
如果这段音乐的音高走向与来源段落差太多，就放弃照抄、交给旋律走向。

代价是同档位相似率从 48% 降到 27~30%（随机基线 25%），但那些「相似」本来就是错的。
另外用音级指纹（每小节 12 维 chroma）尝试过自动识别真正的重复段落，实测真实混音里
相似度最高只有 0.6，不够可靠，所以它只作为高置信通道保留，主力仍是音高闸门。

两个实现上的坑：
- **trill 只覆盖两根键**，整段都用会让音符堆在中间两轨。所以 trill 隔小节出现，其余小节用 roll 走满四轨
- **照抄键位表会破坏手平衡**（实测一度变成左右 59:41）。查表结果还要过一遍
  「单手占比 > 70%」「单键占比 > 29%」两道闸门，超了就交回加权选择

### 长条：为什么不能"连续"

早期版本是「按概率把单点随机变成长条」（EASY 16% / NORMAL 10% / HARD 5%）。实测下来
EASY 有 **11.8%** 的音符是长条（人类谱面 5.7%），而且其中 25% 是"两根长条头隔不到 2 拍"，
41% 的长条尾巴后面 0.35 拍内还有同轨音 —— 也就是**松手就得立刻再按**。这就是"反人类"的来源。

现在的做法是四件事：

1. **只写在接得住的地方**：同轨后面必须留出 0.75~1 拍的空白（人类 p50 是 0.75 拍）
2. **长度由声音决定**：沿 RMS 包络走，声音塌到 45% 以下就是天然尾巴，再吸附到 1/2 拍网格
3. **成段出现**：先给每个小节挑一个最好的候选，再把相邻小节连成 2~4 小节的"长条短语"，
   全曲最多覆盖一半小节（人类是 30% 的小节含长条，但会连着出现）
4. **留呼吸**：两个长条头至少隔 2~3 拍；同一只手在长条结束后也要空 1 拍；
   长条期间同手还要打的音有上限（EASY 每拍 2 个）

改动后（Spectra Loop，128 BPM）：

| 难度 | 长条数 | 占比 | 最长连续链 | 松手即按 | 尾巴离线 | 含长条小节 |
| --- | --- | --- | --- | --- | --- | --- |
| EASY Lv4 | 1 | 0.4% | 1 | 0% | 0% | 2.2% |
| NORMAL Lv8 | 4 | 1.0% | 1 | 0% | 0% | 8.7% |
| HARD Lv12 | 6 | 1.2% | 1 | 0% | 0% | 13.0% |

后来又按 Sparebeat 官方谱面调了两条更关键的：**长条期间把这一小段让给它**
（Sparebeat 实测长条期间只有 7% 的情况别的轨还有音，我们之前三轨照打），
以及**长条头只能落在 1/2 拍网格上**（Sparebeat：66% 整拍、29% 反拍、0% 奇数十六分位）。

**为什么不照抄人类的"密集长条"**：osu!mania 的长条松手早了只扣分，仍算过；
本作松手早于尾巴 0.3 拍直接 MISS。同一条谱，规则一换手感就是两回事 ——
所以密度跟着人类走，间隔比人类更宽。

#### 长条：从"4 小节短语"改成"逐个落地"

长条数量长期只有官方的 1/4（HARD 4 根 vs 19 根）。查下来不是候选不够
（HARD 有 377 个候选、预算 19），而是**挑选模型不适用了**：

旧逻辑先按"4 小节短语"分组、每句只取中段。这套假设是"候选只出现在少数小节"——
在按能量排谱的年代成立。改成按人声排谱之后**几乎每个小节都有候选**，于是
"连续候选小节"只剩 1~2 段长串，短语数 = 2，最终只落地 4 根，预算 19 根本没用上。

现在直接按分数从高到低逐个试，约束四条：
头部间隔（HARD 2 拍）、同轨/同手不重叠、含长条小节总数上限（coverage）、
连续不超过 `phraseBars`（2）个小节。另外**唱出来的音（`sustain`）加权 2.4 倍** ——
长条本来就是在写"这个音持续着"，人声的延长音是最硬的依据。

world.execute(me)：长条 2 / 10 / 19 根（占 0.37% / 1.34% / 2.21%），
官方是 0.3 / 1.4 / 2.1%，长度中位都是 1 拍，最长连续链 ≤2。

### 和 Sparebeat 到底差多少

Sparebeat 的谱面是**纯文本网格**（`/play/<id>/map`）：一行一小节，`,` 切成 16 格，
一格内可以有多个字符就是和弦；`1-4` 普通音符、`5-8` Attack、`a-d`/`e-h` 长条头尾、
`( )` 三连音模式。`node tools/distill_sparebeat.mjs` 会抓 56 首官方曲（165 张谱）解析成时间轴，
再用**和自动谱面完全一样的那把尺子**量一遍（`tools/compare_human.mjs`，详见 `tools/compare_report.md`）。

| 指标 | Sparebeat normal | 本作 NORMAL | Sparebeat hard | 本作 HARD |
| --- | --- | --- | --- | --- |
| NPS | 4.38 | 4.56 | 6.17 | 5.30 |
| 1/4 拍（十六分）时值 | 4.1% | 0% | 24.8% | 0% |
| 双押以上 | 11.9% | 15.0% | 23.3% | 32.6% |
| 每小节踩正拍 | 91.8% | 100% | 93.5% | 100% |
| 长条占音符 | 1.4% | 1.0% | 2.1% | 1.1% |
| 含长条的小节 | 6.3% | 6.5% | 7.9% | 10.9% |
| 相邻小节节奏**完全相同** | 19.8% | 6.7% | 14.0% | 17.8% |
| 相邻小节节奏相似度 | 67.7% | 81.7% | 71.1% | 78.8% |

**量出来的三个真问题**：

1. **双押率根本不受控**。`planBar` 里算了个 `base = chordBase * (...)` 但**从来没被用到**，
   双押概率被写死成「重音位 0.92」。更糟的是判断「是不是重音位」时用的是
   `relBeat % 1`（拍内位置）去索引 16 格的小节掩码，索引空间对不上，
   几乎处处命中 —— 于是 HARD 有 **61%** 的音群是双押（Sparebeat 23%），听起来很吵。
   修好后 NORMAL 14% / HARD 27%，和 Sparebeat 基本对齐。
2. **长条撒得太开**。Sparebeat 的 long note 是「局部现象」：只有 8% 的小节含长条、
   最长连续 2 小节、占音符 2%，而且**长条期间只有 7% 的情况别的轨还有音**。
   我们之前是 24~45% 的小节都有长条，而且只在同轨删音、别的轨照打 —— 这就是
   「中间夹一个长条很难受」。现在长条一出现就把这一小段让给它。
3. **动机对不齐的真凶是双押随机化**，不是音符时间。我先写了一个「把第 2 小节整行抄成
   第 1 小节」的模板步骤，加进去一量：`moved = 0, dropped = 0` —— 小节的**落点本来就
   是一致的**，真正让相邻小节节奏型不一样的是 `chordProb = 0.85`：同样一个格子，
   这一小节加倍、下一小节不加倍，节奏型就差了。
   把重音位改成「定了就每次都加倍」（`chordProb = 1`，密度改由重音位数量控制）之后，
   完全相同率 NORMAL 8.9% → 11.1%、HARD 2.2% → 11.1%，那 60 行模板代码随即删掉。

**还有一处死代码**：`fillRate` / `fillDiv` 两个配置项从头到尾没人读（只有 `gridDiv` 在用）。
以前调 `fillRate` 调了半天没反应就是这个原因。现在十六分连打改由 `maxRunSlots` /
`maxPairs` 直接控制骨架里允许的相邻格数量 —— 注意 128 BPM 的小节比 Sparebeat 的
185 BPM 长，同样 NPS 下必然需要更多十六分，所以 HARD 这一列还是偏高。

### 把谱面的"发声"混进原曲，量一下像不像

`tools/match.html`：把音符按游戏里的打击音（短促三角波，1180/1560 Hz）渲染成一条音轨，
按游戏内音量比混进原曲，再对**混合前后**各抽一次特征，然后比。

跑 `http://127.0.0.1:8777/tools/match.html`，得到：

| 谱面 | 音符 | 包络相关 | 随机基线 | 平移 1/4 拍 | 踩点提升 | 混音后特征相关 | 音符处响度 +dB | 凭空重音 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| EASY | 241 | 0.488 | 0.024 | −0.24 | 3.37× | 0.990 | +0.79 | 0 |
| NORMAL | 388 | 0.538 | 0.038 | −0.28 | 3.16× | 0.985 | +1.14 | 0 |
| HARD | 444 | 0.536 | 0.011 | −0.18 | 3.14× | 0.982 | +1.28 | 0 |

怎么读：

- **包络相关**：音符包络 vs 原曲击打强度曲线。随机撒音是 0.01~0.04，我们是 0.49~0.54；
  把音符整体挪 1/4 拍，相关立刻变负 —— 说明对齐是真的，不是统计幻觉。
- **踩点提升**：音符时刻的击打强度 ÷ 全曲平均。随机是 1.5~1.6×（因为重音本来就扎堆），
  我们是 3.1~3.4×。
- **混音后特征相关 / 凭空重音**：把发声轨混进去之后，特征曲线的形状几乎不变（0.98），
  也几乎不产生"原曲那里本来是安静的"新重音（0 个）—— 谱面没有在音乐之外自己乱响。
- **音符处响度 +1 dB 左右**：打击音是听得见的，但被原曲盖住大半，不会喧宾夺主。

**这个工具直接抓到两个问题**：

1. 补音门槛只有 `strengthAt >= 0.035`，等于"只要有一点声音就补"，HARD 的踩点提升
   只有 2.8×。提高到 0.05~0.06 并加一条"隔壁格已经有明显更响的音就别补"之后，
   HARD 的包络相关 0.47 → 0.54、踩点提升 2.88 → 3.14。
2. **原来 34% 的十六分音有相当一部分是编出来的**。去掉这类补音后，十六分占比掉到 0%
   —— 这首 128 BPM 的曲子里本来就没有那么多十六分音，之前的高密度是补音补出来的，
   听着"密"但不踩点。代价是 HARD 从 6.09 NPS 降到 5.30（等级 12 → 11，
   正好等于 Sparebeat hard 的中位等级）。

### 全曲库回归：只听谱面，能还原多少音乐

`tools/batch-eval.js` + `tools/batch-report.mjs`：把 Sparebeat 官方曲目的**音频和谱面一起**
拉下来（`tools/fetch_sb_audio.mjs`，54 首 / 321 张谱），对每首歌同时做两件事 ——
用官方三档谱面量一遍，用我们自己的分析器生成三档谱面再量一遍。

量的是「**只看谱面，能不能还原出音乐**」：按小节把 16 个十六分格对齐，
比较谱面「有音」的格子和音频能量达到本小节峰值 50% 的格子。用的是 f1（加权 F1）。

#### 两个口径坑（踩过才知道）

1. **时钟差 35ms**。官方谱的音符比音频瞬态**晚约 35ms**，这是谱子之外的固定错位。
   三种独立方法在 54 首上量过：

   | 方法 | 结果 |
   | --- | --- |
   | 官方音符 → 最近「检测 onset」的有符号距离 | 中位 **+37.8ms**（只取音符 60% 以上落在 onset 上的 16 首：+34.8ms） |
   | 官方音符 → 「波形最大上升沿」的距离 | 中位 **+29ms** |
   | 让「音符处能量」最高的整体平移（1ms 精扫） | **−40~−70ms**（按 21ms 帧量化后与上面一致） |

   我们自己的检测 onset 到波形上升沿是 **−0.7ms**，所以不是检测器偏早。
   不做这个校正，所有「0 偏移」的对比都在扣官方谱的分。
   实现在 `tools/sparebeat.mjs` 的 `CHART_LAG_MS = 35`，只在**拿谱面和音频对比**时启用
   （`parseSparebeat(data, diff, { alignAudio: true })`），谱面本身的时间轴不动。

2. **小节长度会被自己的 BPM 带跑**。f1 是「每小节 16 格」，如果用自己的 BPM 当网格，
   BPM 判错成八度时小节变长、每个格子翻倍宽，f1 就虚高 —— 实测 ×0.5/×2 的曲子 f1 **0.643**，
   反而高于 BPM 判对的 **0.601**。所以现在**两侧都用官方 BPM 的网格**，这一列才有可比性。

#### 结果（54 首 / 321 张谱）

| 来源 | 难度 | 谱数 | f1 | 人声% | 只踩镲% | lift | 最优 lift | 小节线对齐 | 偏移中位 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Sparebeat | easy | 52 | 0.438 | 53% | 14.7% | 1.59 | 1.74 | 21% | −30ms |
| Sparebeat | normal | 53 | 0.555 | 52% | 14.8% | 1.54 | 1.66 | 23% | −30ms |
| Sparebeat | hard | 54 | 0.647 | 49% | 14.0% | 1.50 | 1.62 | 23% | −30ms |
| 本作 | easy | 54 | **0.492** | 62% | 13.4% | 1.66 | 1.67 | 33% | −20ms |
| 本作 | normal | 54 | **0.581** | 56% | 13.2% | 1.59 | 1.60 | 32% | −20ms |
| 本作 | hard | 54 | 0.613 | 53% | 13.2% | 1.57 | 1.58 | 30% | −20ms |

同曲对拍（官方 − 本作，正数 = 官方更贴音乐）：easy **−0.055**（本作更好的 39/52 首）、
normal **−0.027**（31/53）、hard **+0.034**（19/54）。

**人声% / 只踩镲%**：每个音符映射到最近的检测起音，看它是不是「稳定音高、在人声音域」
的起音（人声%），或者只是个踩镲（只踩镲%）。官方谱 53/52/49% 人声 + 14% 只踩镲。
接入节奏词汇之前我们是 69/64/61% —— 高得离谱，说明"每个音节都写一个音"；现在是
62/56/53%，反而更接近人类。

**密度**（每小节音符）：easy 4.4 / normal 6.6 / hard 7.9，官方 4.25 / 6.80 / 9.46。
EASY、NORMAL 对齐，HARD 仍稀 1.5 个/小节 —— 差的是鼓点细节，不是旋律。

**怎么读这张表**：

- **EASY 赢 0.055，NORMAL 赢 0.027，HARD 落后 0.034**。HARD 的差距从 0.075（BPM 修对前）
  → 0.050（按音节排）→ 0.034（节奏词汇），位置始终没变：官方每小节比我们多写 1.5 个音。
- **HARD 那 1.5 个音的位置也很明确**：官方硬谱会用一部分 16 分鼓点填空。
  补到 9.5 的代价是"只踩镲"从 13% 涨到 25% 以上，试过，听着又变回"跟着镲走"。
- **小节相关我们更高**（0.29 vs 0.12）。因为我们的音符本来就是按小节能量排的，
  这等于"用答案改卷子"；官方谱师不看能量曲线，他们听的是乐器。这一列别当优势看。
- **lift 也别比**（1.63 vs 1.50）：我们的音符从同一套 onset 检测里出来，天然贴着自己的检测结果。

#### BPM：tempo-octave 搜索（43% → 93%）

之前是「一个初始估计 + {×1.5, ×2/3} 两个候选」：真值不在候选里就永远纠不回来。
54 首官方曲对照，检出值与真值的比值有 **0.64 / 0.69 / 0.81** 这种非整倍率 ——
说明自相关锁到的可能是一段"附点八分 / 五连音"周期，在一条 3:2 的梯子上怎么找都不对。

现在直接在 **70–230 BPM 上扫**（步长 0.25），打分三项相乘：

```
salience(拍长) = nac(拍长) − mean(nac(0.6~1.4×拍长) 去掉自身 ±6%)   # 归一化自相关 − 局部基线
score(bpm)     = [ salience(拍) + 0.5 × salience(4 拍) ]             # 加上小节周期
                 × (0.55 + 0.45 × 对数正态先验(bpm; 中心 165, σ 0.55))
```

- **归一化**（余弦，`Σab / sqrt(Σa²Σb²)`）：不除以能量的话，数值高低取决于整首响度，
  比不同长度的 lag 等于用两把尺子。实测归一化本身不改变命中率（都是 80%），
  但它是"能跨 lag 比较"的前提。
- **减局部基线**：短 lag 天生比长 lag 更相关（包络平滑），不减会系统性偏向快的那层。
  54 首『真值必在候选里』的对照：80% → 85%。
- **小节项（4 拍）**：谱面是按 4/4 写的，光看拍点时"半速"读法和小节线都自洽，分不开。
  加上小节项之后 54 首里多对 20 首（这是提升最大的一项）。
- **节拍先验**：只用来打破八度平手（45% 权重）。官方 54 首 BPM 中位 165、范围 76–222；
  证据明显更强的那层照样能赢（76 BPM 那首就是先验想抬到 152、但证据不够，最后保住 76）。
  先验中心取 150 / 165 / 180、σ 取 0.45 / 0.55 / 0.7 结果都一样，不是调出来的临界值。

**两个坑**：

1. `ac[]` 原来只从 0.28s 起算，短 lag 留 0。局部基线会采样到 0.17s 这一带，
   基线被压低 → 打分系统性偏向快的那层，端到端 BPM 全部偏大 1.5 倍。
   改成从 2 帧算起才对上离线实验的结果。
2. `lagMax` 要放到 2.0s：小节项要算 4 拍，70 BPM 时 4 拍就是 3.4s，够不到的那几档跳过
   小节项（再放长到 3.5s 反而会把 155 那首带偏，实测过）。

**结果**：BPM 与官方相差 ≤2% 的 **43% → 93%**（54 首），倍数错 2/54，1.5 倍族错 0/54。
剩下的 3 首是 76→152、102→204、141→192，都是"半速 / 1.36 倍"读法，
音乐上说得通（很多 76 的曲子确实按 152 记谱），没有继续压。

### 节奏型：从「每个音节一下」到「节奏词汇」

`world.execute(me)` 打起来"完全没有节奏感"。量出来原因很具体：**HARD 有 48% 的音落在
踩镲上，而且每小节的节奏型是均匀的八分音符流**（`N.N.N.N.N.N.N.`）—— 音都在声音上，
但每一拍分量相同，听不出句读。

根因是骨架由「4 小节对应槽位的**平均**击打强度」挑出来的。踩镲每半拍一下、四小节里
完全一样，平均之后就是一条直线。

#### 第一步：跟着"唱"走（不够）

`js/analyzer.js` 4.5 先给每个起音补上音高与"是否延续"的判断（`sustain`），
`js/chart.js` 3.3 / 3.4 把「YIN 稳定 + 可信度 ≥0.45 + 音高在 G2–A#5 + 够响」的槽位
当成音节，一小节 ≥2 个就按音节排：

| 指标（world.execute(me)） | 改前 | 只按音节排 | ＋长音召回 |
| --- | --- | --- | --- |
| 音符落在检测到的起音上 | 76.0% | 90.0% | **91.2%** |
| 落在人声起音上 | 53.1% | 69.2% | **80.3%** |
| 只落在踩镲上 | 13.8% | 5.7% | **1.5%** |

但这一步只解决了"音落在什么声音上"，没解决"节奏型长什么样"：**8 个音节就是 8 个音**，
一整小节又变回均匀八分。人写谱不会这样 —— 它会挑一个可辨认的节奏格，允许丢掉一部分弱音节。

#### 第二步：节奏词汇表（现在的做法）

参考文献里的做法（Time-based Chart Partitioning, AIIDE'25；TaikoNation, FDG'21）：
人类谱师不是每小节独立算一遍，而是用**一小批固定节奏型**拼歌。

`tools/build_patterns.mjs` 把 Sparebeat 官方 54 首 / 162 张谱的每个小节压成 16 位掩码
（不分轨道，只记"哪几格有音"），统计频次，保留覆盖 72% 小节的那批：

| 难度 | 小节数 | 不同型 | 保留 | 最常见的型 |
| --- | --- | --- | --- | --- |
| easy | 3611 | 179 | **19** | `1...1...1...1...`（22.9%，四分音符） |
| normal | 3654 | 367 | **54** | `1.1.1.1.1.1.1.1.`（10.4%，八分） |
| hard | 3564 | 510 | **87** | `1.1.1.1.1.1.1.1.`（17.0%） |

每个型还带两样统计：**双押写在哪些格**（`c`，十分位）和**后面通常跟哪个型**（`TRANS`，
一阶马尔可夫）。生成时（`js/chart.js` 3.42）：

```
对每一小节：
  att[i] = 音频强度（归一化）；人声槽位强制 = 1.0
  在词汇表里挑型（|n − 密度目标| ≤ 1）：
     拒绝：型里有格子既没声音也不是音节（不能凭空按）
     拒绝：丢掉超过 30% 的音节（人写谱会丢弱音节，不会丢三成）
     打分：(Σ att − 0.45×丢掉的音节) / √n
           + 0.04·log(1+频次)      ← 人类越常用的型越优先
           + 0.13（与上一小节同型） ← 动机
           + 0.14·P(该型 | 上一型)  ← 语序
  双押位置直接取该型的统计值，不按本小节音量重算
```

**结果**（`world.execute(me)`，130 BPM，HARD）：

| 指标 | 按音节排 | ＋词汇表 | Sparebeat 官方（54 首中位） |
| --- | --- | --- | --- |
| 落在检测到的起音上 | 90.0% | 80.3% | — |
| 落在人声起音上 | 80.3% | 63.3% | 49% |
| 相邻小节节奏**完全相同** | 0.0% | **10.8%** | 14.0% |
| 相邻小节节奏相似度 | 54% | **78.2%** | 71.1% |

落在起音上的比例降了 10 个点，是**故意**的：词汇表会在"音节密集但没有节奏骨架"的地方
少写一个音、在"有骨架但音节弱"的地方补一个。换回来的是每个小节都有可辨认的形状，
且相邻小节的形状终于开始重复（0% → 10.8%）。

54 首回归同时也在涨（f1 0.483→**0.492** / 0.570→**0.581** / 0.601→**0.613**），
"人声落点"从 69/63/61% 回到 56/52/50%，反而更接近官方的 53/52/49% —— 说明
少写的那些音本来就是对得"过头"了。

#### 走过的一条死路：真正的强拍检测

顺手量了一下小节相位：`firstBeat` 只是**拍点**相位，小节线是"从它往后数 4 拍"推出来的，
所以 54 首里只有 **44%** 的小节线真的落在音乐的小节上（其余偏 1~3 拍）。相位错了的话，
"正拍加成""双押压在强拍"这类规则全部落在错的位置。

试过用音频判强拍，全部失败（54 首、真实小节线做答案）：

| 判据 | 命中 |
| --- | --- |
| 低音能量最强的一拍 | 32% |
| 鼓组模板（底鼓 1/3 + 军鼓 2/4）相关 | 28% |
| 起音强度最强的一拍 | 38% |
| 不修正（假设相位全对） | 44% |

把真实相位下的四拍剖面导出来看就明白了：底鼓 `1.02 / 0.97 / 1.03 / 0.97`（1、3 拍强，
只能分辨奇偶），军鼓 `1.01 / 1.00 / 0.99 / 1.00`（**平的**，backbeat 在这批电子曲里
根本不在 450–4500Hz 的通量上）。**剩下那 50% 的二义性靠纯信号处理是无解的** ——
这正是 BeatThis（ISMIR'24，MIT，有 ONNX 导出）这类模型解决的问题，代价是 83MB
（或 small0 的 9.6MB）+ ONNX Runtime，对一个无构建、纯静态的网页音游来说太重。

所以改成了**让规则不依赖强拍**：双押位置改成由节奏型本身的统计决定（词汇表给），
正拍加成退化成"节拍内位置"（`slot % 4`，相位无关）。小节相位错的曲子不再被强加错的重音。

- `node tools/distill_holds.mjs` —— 从真实谱面蒸馏长条规律（长度 / 间隔 / 尾巴）
- `node tools/compare_human.mjs` —— 人类谱面 vs 本站谱面的对比表（写 `tools/compare_report.md`）
- `http://127.0.0.1:8777/tools/holdstats.html` —— 浏览器里量当前谱面的长条指标（`?dump=1` 可导出音符）

（`pcm.raw` 用 `ffmpeg -i x.mp3 -ar 48000 -ac 1 -f s16le x.raw` 生成）

难度等级由实际 NPS 反推（同一首歌每次生成结果一致，随机种子由 BPM + 时长决定）。

## 参考：这个领域已经有人做过的

谱面自动生成是一个正经的研究方向，下面这些是真正读过、并且取了东西的（不是"顺便提一句"）：

| 来源 | 关键做法 | 我们取了什么 |
| --- | --- | --- |
| **Time-based Chart Partitioning**（Hanzen et al., AIIDE'25） | 神经 onset 检测 + 符号化 beat snapping + 按时间分段做模式匹配 | 整个「节奏词汇表」的思路：把谱面切成小节、用一小批型去匹配，而不是逐音独立决策 |
| **TaikoNation**（Halina & Guzdial, FDG'21） | 以 pattern 为中心的生成，强调局部连贯 | 同上；以及"相邻小节要成句"的评价指标（motif / 相似度） |
| **AutoOsu**（Lee & Jeong, ISMIR'23） | 把 onset 检测和键位分配联合训练，条件在难度上 | 结论是"键位分配不该脱离音频"—— 我们的键位跟着音高走，没有单独随机 |
| **goct**（Yi et al., ISMIR'23） | 4 拍对齐的 log-mel → token 序列；micro-F1 评测 | 按小节 16 格对齐再算 f1 的评测口径；`tools/batch-eval.js` 就是照这个做的 |
| **Ensomi R2**（osu!mania 4K，AGPL） | 先拟合节拍网格 → "rows model"决定哪里起音 → 再排键位/长条；带语料库参照评测 | "先定时间轴、再排键位"的分层；以及"拿语料库分布当基准"而不是只看绝对分数 |
| **Beat This!**（Foscarin et al., ISMIR'24） | Transformer 直接吐 beat / downbeat logits，不需要 DBN 后处理 | 想用，但没装：83MB（small0 也有 9.6MB）+ ONNX Runtime，对无构建的静态站点太重。**如果以后允许上模型，这是第一个该上的**（见「走过的一条死路」） |
| **Mapperatorinator / osumapper / osu!dreamer** | 端到端序列模型生成 osu! 谱面 | 只读结论：它们都要求"音频 → 谱面"是序列问题，且训练集得上万张。我们没有训练预算，所以走"统计 + 规则"这条路 |

**为什么不上神经网络**：这个项目是零构建、纯静态、在浏览器里跑，模型文件要么 10~83MB
要么得自带推理引擎。在 54 首官方曲上，规则方案（BPM 93%、f1 0.49/0.58/0.61）已经接近
官方谱（0.44/0.56/0.65），而一个 10MB 的模型能补的主要是「小节相位」这一项 ——
收益明确但不值得为此把整个架构改掉。这条判断写在上面那张表里，将来要翻案也有据可查。

# SPECTRA · 音游锻造所

**▶ [在线试玩](https://xinyi-she.github.io/spectra/)** · 内置示例曲打开即玩（B 站转换需本地运行）

上传任意音频（MP3 / WAV / M4A / OGG / FLAC），浏览器里现场分析节拍、生成 EASY / NORMAL / HARD
三档 4K 谱面，直接开打。规则参考 [Sparebeat](https://sparebeat.com/)，全程本地运算，音频不上传服务器。

## 运行

模块化 + `fetch` 需要 http 服务（不能直接双击 html）。

**最省事：双击 `启动.bat`** —— 自动找可用的 Python、启动服务、打开浏览器。

命令行方式：

```bash
cd beatforge
python tools/serve.py 8777      # 浏览器会自动打开 http://127.0.0.1:8777/
```

参数：`python tools/serve.py [端口] [--no-open]`。重复执行不会起第二个实例，
检测到端口上已有本服务时直接复用并打开浏览器。

### 敲了命令但网页没反应？

Windows 上最常见的坑：`python` 命令指向的是 **Microsoft Store 的占位程序**
（`AppData\Local\Microsoft\WindowsApps\python.exe` 是个重定向器，不是真 Python），
敲下去只会弹应用商店、什么都不执行。判断方法：

```bash
where python        # 输出里有 WindowsApps\python.exe 就是踩坑了
python --version    # 没有版本号输出 = 没装真正的 Python
```

两种解法：

1. 双击 `启动.bat`（推荐，会绕开占位程序）
2. 装一个真 Python（python.org，安装时勾选 *Add python.exe to PATH*）

其它排查：端口被别的软件占用就换一个，例如 `python tools/serve.py 8899`；
服务端日志在 `tools/server.log`。

## 三种进歌方式

1. **曲库**：首页直接点卡片（内置两首 B 站投稿转出的音频）
2. **本地上传**：拖入 / 选择 MP3、WAV、M4A、OGG、FLAC。分析完会存进浏览器（IndexedDB），
   曲库里留一张卡 —— 刷新页面、关掉浏览器重开都还在，最多保留 20 首
3. **B 站链接**：粘贴 `https://www.bilibili.com/video/BV…`、`BV 号` 或 `b23.tv` 短链，
   本地服务会解析、下载音轨（192kbps）并缓存到 `assets/cache/<BV号>/`，之后秒开

> 浏览器直连 B 站会被 CORS 和 Referer 校验拦住，所以这一步必须由 `tools/serve.py` 代理。
> 用 `python -m http.server` 也能玩曲库和上传，但 B 站链接会提示接口不可用。

首页还有 **我的记录**：每首歌按 EASY / NORMAL / HARD 分别保存最好成绩、评级、最大连击，
曲库卡片左上角会显示最好评级。数据都在 localStorage（`spectra.records`），可一键清空。

## B站转 MP3 工具页

首页右上角「**B站转 MP3**」，或直接开 `/convert.html`。

- 一次粘贴多个链接（换行 / 空格分隔都行），逐个解析
- 卡片显示封面、标题、UP 主、时长、文件大小、码率
- 「下载 MP3」存到本地，文件名是 `标题 - UP主.mp3`
- 「打音游」带着这首直接进游戏（等价于 `?bili=BV号`）
- 转换记录存 localStorage，下次打开可直接重新下载
- 音轨缓存在 `assets/cache/<BV号>/`，同一首再来一次秒出

错误信息做了翻译：BV 号写错、稿件已删、私密视频、审核中都会给出具体原因，
不会冒出 `KeyError: 'data'` 这种半截报错。

> 依赖 `tools/serve.py`。静态部署（GitHub Pages）上会直接提示「本地服务未连接」。

## 谱面是怎么「AI 生成」的

`js/analyzer.js` + `js/chart.js`，不调用外部模型，纯信号处理 + 规则编排：

1. **STFT**：单声道 → 汉宁窗 FFT（44.1/48k 下 2048 点，hop ≈ 23ms）
2. **多频段谱通量**：bass / low / mid / high / air 五个频段分别做正向差分，各频段按 p97 归一后加权求和 → 击打强度曲线
3. **峰值拾取**：自适应阈值（局部均值 ×1.18）+ 局部极大 + 55ms 最小间隔 → 音符候选点，并标注频段特征（kick / snare / hat）
4. **BPM**：自相关做粗估 → 用「相位相干」精修（这一步很关键，129.3 → 130.0 的偏差会让整首歌漂 2 拍）→ 全拍搜索确定拍点相位 → 最小二乘拟合整曲网格
5. **吸附到网格**：原始 onset 相对拍点有 ±20ms 抖动（实测平均 22.6ms 偏差），直接排谱会显得「松 / 慢半拍」。所以先按 1/4（EASY/NORMAL）或 1/8（HARD）拍吸附、同格只留最强音。吸附后偏差降到 7.8ms，音符 100% 落在网格上
6. **强度曲线 → 密度**：按小节统计 RMS（响度）并平滑归一化成 0..1，混入该小节的击打点数量；
   每小节的目标密度 = 在该难度的「安静 NPS」和「高潮 NPS」之间插值 —— 主歌留白、副歌加密，密度和响度的相关系数实测 0.77~0.96
7. **基频检测**：每个 onset 取出 58ms 窗口做 YIN，得到音高与可信度（见下一节）
8. **谱面编排**：先按小节目标密度定出完整时间轴（选音 + 补连打），再统一排键位。
   键位不是随机游走，而是「**有旋律就跟着旋律，没旋律就套语汇**」：
   - 这一段有 60% 以上的音能测出可信音高 → **音高步进**（±1 格，本身就是 roll 形态）
   - 否则按节奏型套语汇：等间隔连打（1/8 或更密）→ roll（0123 / 3210）或 trill（两键交替）
   - 零散音 / 弱拍 → 加权跳，权重里综合了 5 条手感规则
   - 只有**强拍且足够炸**的位置才给双押，且按舒适度选第二键（外外 > 外内 > 内内 1-2）
9. **五条手感规则**（每条都对应一个具体的「难打」原因）：
   - **同键连打**（jack）重罚。唯一的例外是「音高完全相同」—— 那是音乐上真正的重复音，
     允许写成 jack，概率按难度给（EASY 0.1 / NORMAL 0.45 / HARD 0.9）
   - **交替加分**：上上个键正好是当前候选时给高权重，天然生成 trill（4K 里最舒服的形态）
   - **手平衡**：近期哪只手用得少就往哪边偏
   - **锚点抑制**：最近 8 个音里某根键出现过多就压权重
   - **大跳降权**：相邻移动最顺手，跨 3 个键的跳按难度打折
10. **长条**：只写在「接得住」的位置 —— 同轨后面留出呼吸、头落在 1/2 拍网格、
    长度由声音延续决定（见下方「长条：为什么不能连续」）
11. **开场缓冲**：谱面第一颗音强制落在 **3.4 秒之后、且压在小节线上**（128 BPM 下是第 3 小节）。
    之前只挡了 0.8 秒，一上来就有音的曲子会「一开播就开打」，完全没有准备时间；
    游戏端再兜一层：万一第一颗音还是太近，就先静音等够 3.4 秒（`audio.play(from, delay)`），
    这期间谱面时间是负的，倒计时照走
12. **收尾**：重音处生成特殊音符，最后用 1 秒滑动窗口限制 NPS（3.6 / 6.2 / 9.6）保证可打

### 旋律：从混音里测出音高

`js/pitch.js`，YIN 算法。难点不在算法本身，而在「复音混音里到底该听谁」：

1. **降采样到 12kHz**（先做抗混叠），搜索 90~1100Hz —— 覆盖人声、吉他、主奏
2. **先滤掉贝斯**：高通 170Hz ×2 + 低通 1600Hz。这一步是必须的 ——
   110Hz 与 220Hz 的**共同周期是 110Hz**，YIN 会给出一个「低八度」的答案，
   实测不做滤波时整首歌的音高全部低 12~24 个半音
3. **窗口从 onset +16ms 开始**：起音瞬态没有稳定周期，会把估计拉偏
4. **不做八度校正**：YIN 的规则是「取第一个足够低的谷」，2T / 3T 同样是合法周期，
   越往后越容易落到低八度。曾经加过「2 倍周期也合格就取 2 倍」，实测把整段旋律压低八度，已删
5. **稳定性闸门**：复音里 YIN 会在贝斯 / 人声 / 吉他之间来回跳，实测相邻两音的
   音高差常在 7~11 个半音 —— 那是换了声部，不是旋律。所以只保留「附近还有音高相近的音」
   的检测结果，孤立的跳变当成不可信
6. **3 点中值滤波**：削掉残留的单点尖峰，真实的大跳保留

**精度实测**（`node tools/test_pitch.mjs`）：合成的 12 音旋律，即使叠上底鼓、军鼓、
低频贝斯和高次泛音，也是 12/12 全部检出，**中位误差 1 音分、全部在 25 音分内**；
白噪声的可信度 0.11（门槛 0.5），打击乐能被正确排除。

真实歌曲的音高覆盖率 68~77%（《十重告别》76.6%，中位 217Hz ≈ A3），
测出的音高 100% 落在人声/主奏的合理区间。

### 音高 → 键位

拿到音高之后要回答一个问题：**4 个键怎么表达一条旋律？**

- **走向**：音高上升 → 键位右移，下降 → 左移；幅度按音程大小给 1~2 格
- **边界环绕而不是反弹**：4K 里 3→0 本来就被读作「继续上行」（roll 就是这么走的）。
  早期版本用反弹，结果旋律一上行键位反而左移，跟随率只有 50%
- **同一个音** → 允许落在同一个键上（真 jack），但只连两个
- **绝对音高**：偏高的音往外侧（0 / 3）偏，偏低的往内侧（1 / 2）偏 —— 对应「高音走外侧」
- **补音**：16 分补出来的音没有音高，按前后可信音高做**线性插值**（当作经过音），
  否则连打里「有音高」和「没音高」会交替出现，旋律线被切碎

实测「旋律跟随率」（相邻两音的音高变化方向与键位移动方向一致的比例）：
《十重告别》HARD **68%**、NORMAL 60%；《world.execute(me)》HARD 60%、NORMAL 61%。
随机分配的理论值约 50%。

### 节奏先验：从真实谱面蒸馏

前几轮的规则都是人手调的，难免主观。这一轮换成"先量真实谱面，再照着改"：

**语料**：osu!mania 4K 共 **160 张谱面、479,479 个音符**（osu.direct 公共镜像，
只下载 `.osu` 文本，每个约 50KB；只做聚合统计，**不包含任何原谱内容，也不重新分发**）。
抓取见 `tools/fetch_charts.py` / `tools/fetch_charts.mjs`，统计见 `tools/distill.mjs`，
产出的常量在 `js/chart-priors.js`。

量出来的几条关键事实：

| 事实 | 数据 |
| --- | --- |
| 相邻两个音的时值 | **52% 是 1/4 拍**，6% 是 1/8 拍，7% 是附点（3/16），其余 34% 更长 |
| 音符落在拍内什么位置 | 正拍 30%、半拍 26%、1/4 拍位 15%、3/4 拍位 16%，其余位置合计不到 13% |
| 双押以上占多少 | **40%**（双 29.7%、三 7.3%、四 3.0%） |
| 双押落在哪 | 正拍 **49%**、半拍 28%、3/4 拍 10%、1/4 拍 9% |
| 同键连打 | 快速（<1/4 拍）只有 2.2%，慢速 9.9% |
| 相邻小节节奏型完全相同 | **20%**（重音也计入节奏型；只看"有没有音"是 39%） |

对照自己的输出，差距非常明显：

| 指标 | 真实谱面 | 改前（HARD） | 改后（HARD） |
| --- | --- | --- | --- |
| 双押以上占比 | 43.1% | **3.9%** | 49.7% |
| 正拍音符占比 | 32.8% | 30.9% | 43.5% |
| 相邻小节节奏型相同 | 20.0% | **1.9%** | 12.5% |
| 1/4 拍间隔 | 51.9% | 79.4% | 39.8% |

**改前三宗罪**：几乎没有双押（所以没有重音、没有"顿"的感觉）、节奏型每小节都不一样
（所以没有记忆点）、音符均匀铺满十六分网格（像机器在数拍）。

于是改了三处：

1. **双押位置按真实分布撒**：正拍 1.63 倍权重、半拍 1.08、1/4 与 3/4 拍约 0.6、
   非十六分网格 0.2。这样重音压在正拍和半拍上，才有"点头"的支点。
2. **节奏动机 = 短语内的音频共识骨架**：把 4 个小节对应槽位的击打强度平均，
   最强的那 N 格就是这一句的节奏骨架；4 小节复用同一条骨架，末小节翻转两格做变奏。
   动机不是随机抽的 —— 随机抽会和音频对不上，反而更散。
3. **补音按骨架补满**：骨架上的格子只要"有一点声音"就补上（谱师写踩镲也是这么做的），
   而不是"够响才写、写满为止"。骨架就是密度上限，不再往骨架外撒音。

双押会把音符数翻倍，所以密度目标相应下调（HARD 9.9 → 7.0 nps），
最终 HARD 仍是 Lv12 / 7.14 nps，和改前同级。

### 段落结构与一致性

谱面不能每小节都换花样，否则打起来"没有记忆点"。所以先做结构规划：

1. **分档**：按每小节能量分「安静 / 正常 / 高潮」三档，连续同档的小节组成一个段落
2. **主题**：每个档位准备两套「乐句主题」（roll 的方向与起始键、trill 的键对）
3. **复用**：真正的重复段落**共用第一段的键位表**
4. **呼应**：段内后半用变体（roll 反向 / trill 换手），避免整段像复制粘贴
5. **曲线**：句内密度轻微递增（0.9 → 1.1），极安静的小节直接留白，形成 build-up 与 break

**这里有个修正**：早期版本是「同档位就照抄」，把能量相近的段落一律当成同一段音乐。
引入音高之后可以直接验证这个假设 —— 实测同档位段落的**平均音高差有 5~9 个半音**，
它们根本不是同一段音乐，抄出来的键位与旋律无关。所以现在照抄前要过一道**音高闸门**：
如果这段音乐的音高走向与来源段落差太多，就放弃照抄、交给旋律走向。

代价是同档位相似率从 48% 降到 27~30%（随机基线 25%），但那些「相似」本来就是错的。
另外用音级指纹（每小节 12 维 chroma）尝试过自动识别真正的重复段落，实测真实混音里
相似度最高只有 0.6，不够可靠，所以它只作为高置信通道保留，主力仍是音高闸门。

两个实现上的坑：
- **trill 只覆盖两根键**，整段都用会让音符堆在中间两轨。所以 trill 隔小节出现，其余小节用 roll 走满四轨
- **照抄键位表会破坏手平衡**（实测一度变成左右 59:41）。查表结果还要过一遍
  「单手占比 > 70%」「单键占比 > 29%」两道闸门，超了就交回加权选择

### 长条：为什么不能"连续"

早期版本是「按概率把单点随机变成长条」（EASY 16% / NORMAL 10% / HARD 5%）。实测下来
EASY 有 **11.8%** 的音符是长条（人类谱面 5.7%），而且其中 25% 是"两根长条头隔不到 2 拍"，
41% 的长条尾巴后面 0.35 拍内还有同轨音 —— 也就是**松手就得立刻再按**。这就是"反人类"的来源。

现在的做法是四件事：

1. **只写在接得住的地方**：同轨后面必须留出 0.75~1 拍的空白（人类 p50 是 0.75 拍）
2. **长度由声音决定**：沿 RMS 包络走，声音塌到 45% 以下就是天然尾巴，再吸附到 1/2 拍网格
3. **成段出现**：先给每个小节挑一个最好的候选，再把相邻小节连成 2~4 小节的"长条短语"，
   全曲最多覆盖一半小节（人类是 30% 的小节含长条，但会连着出现）
4. **留呼吸**：两个长条头至少隔 2~3 拍；同一只手在长条结束后也要空 1 拍；
   长条期间同手还要打的音有上限（EASY 每拍 2 个）

改动后（Spectra Loop，128 BPM）：

| 难度 | 长条数 | 占比 | 最长连续链 | 松手即按 | 尾巴离线 | 含长条小节 |
| --- | --- | --- | --- | --- | --- | --- |
| EASY Lv4 | 1 | 0.4% | 1 | 0% | 0% | 2.0% |
| NORMAL Lv8 | 5 | 1.3% | 1 | 0% | 0% | 10.2% |
| HARD Lv12 | 7 | 1.3% | 1 | 0% | 0% | 12.2% |

后来又按 Sparebeat 官方谱面调了两条更关键的：**长条期间把这一小段让给它**
（Sparebeat 实测长条期间只有 7% 的情况别的轨还有音，我们之前三轨照打），
以及**长条头只能落在 1/2 拍网格上**（Sparebeat：66% 整拍、29% 反拍、0% 奇数十六分位）。

**为什么不照抄人类的"密集长条"**：osu!mania 的长条松手早了只扣分，仍算过；
本作松手早于尾巴 0.3 拍直接 MISS。同一条谱，规则一换手感就是两回事 ——
所以密度跟着人类走，间隔比人类更宽。

### 和 Sparebeat 到底差多少

Sparebeat 的谱面是**纯文本网格**（`/play/<id>/map`）：一行一小节，`,` 切成 16 格，
一格内可以有多个字符就是和弦；`1-4` 普通音符、`5-8` Attack、`a-d`/`e-h` 长条头尾、
`( )` 三连音模式。`node tools/distill_sparebeat.mjs` 会抓 56 首官方曲（165 张谱）解析成时间轴，
再用**和自动谱面完全一样的那把尺子**量一遍（`tools/compare_human.mjs`，详见 `tools/compare_report.md`）。

| 指标 | Sparebeat normal | 本作 NORMAL | Sparebeat hard | 本作 HARD |
| --- | --- | --- | --- | --- |
| NPS | 4.38 | 4.40 | 6.17 | 5.92 |
| 1/4 拍（十六分）时值 | 4.1% | 3.7% | 24.8% | 35.3% |
| 双押以上 | 11.9% | 11.3% | 23.3% | 24.6% |
| 每小节踩正拍 | 91.8% | 95.9% | 93.5% | 98.0% |
| 长条占音符 | 1.4% | 1.3% | 2.1% | 1.3% |
| 长条长度中位 | 1 拍 | 1 拍 | 1 拍 | 1 拍 |
| 含长条的小节 | 6.3% | 10.2% | 7.9% | 12.2% |
| 相邻小节节奏相似 | 67.7% | 76.8% | 71.1% | 75.2% |

**这次量出来的三个真问题**：

1. **双押率根本不受控**。`planBar` 里算了个 `base = chordBase * (...)` 但**从来没被用到**，
   双押概率被写死成"重音位 0.92"。更糟的是判断"是不是重音位"时用的是
   `relBeat % 1`（拍内位置）去索引 16 格的小节掩码，索引空间对不上，
   几乎处处命中 —— 于是 HARD 有 **61%** 的音群是双押（Sparebeat 23%），听起来很吵。
   修好后 NORMAL 11.3% / HARD 24.6%，和 Sparebeat 基本对齐。
2. **长条撒得太开**。Sparebeat 的 long note 是"局部现象"：只有 8% 的小节含长条、
   最长连续 2 小节、占音符 2%，而且**长条期间只有 7% 的情况别的轨还有音**。
   我们之前是 24~45% 的小节都有长条，而且只在同轨删音、别的轨照打 —— 这就是
   "中间夹一个长条很难受"。现在长条一出现就把这一小段让给它，密度也压到 0.4%/1.3%/1.3%。
3. **长条头的位置**。Sparebeat 实测 66% 落在整拍、29% 在"&"、**0% 在奇数十六分位**。
   现在长条头强制落在 1/2 拍网格上。

还差的：**动机重复**。Sparebeat 相邻小节有 14%~35% 是完全同一个节奏型，我们只有 0~12%
（相似度 75% 对 71%，其实不差）。原因是我们的音符跟着音频 onset 走，
而 Sparebeat 谱师是把一小节**整行复制**过去的。要做这条就得把"节奏型"提到
onset 之上当模板，先记着。

调试工具：

- `node tools/distill_sparebeat.mjs` —— 抓 Sparebeat 官方谱面并量指标
- `node tools/compare_human.mjs` —— Sparebeat / osu!mania / 本作 三方对比表
- `http://127.0.0.1:8777/tools/holdstats.html` —— 浏览器里量当前谱面（`?dump=1` 导出音符）

| 难度 | 音符 | nps | 双押以上 | 同键连打 | 四键占比 | 左右手 |
| --- | --- | --- | --- | --- | --- | --- |
| EASY Lv4 | 245 | 2.74 | 0% | 0% | 25.7 / 27.8 / 22.9 / 23.7 | 53.5 / 46.5 |
| NORMAL Lv8 | 393 | 4.40 | 11.3% | 0.4% | 26.7 / 20.1 / 29.0 / 24.2 | 46.8 / 53.2 |

这里的 jack 基本都来自「音高完全相同的真重复音」——逐个核对过每个 jack 两端的
semi 完全相等（如 48.0 → 48.0），不是随机产生的。

结构校验（三首曲子 × 三档共 9 张谱）全部通过：网格偏差 p90 = **0ms**、
无重复音、无长条重叠、任意 1 秒不超过 NPS 上限。

## 部署到 GitHub Pages

仓库根目录就是站点根，push 上去后：

1. 仓库 **Settings → Pages → Build and deployment**
2. Source 选 **Deploy from a branch**，Branch 选 **`main`**、目录选 **`/ (root)`**，Save
3. 等一分钟，访问 `https://<用户名>.github.io/<仓库名>/`

`.nojekyll` 已经放好，所有资源都是相对路径，挂在 `/<仓库名>/` 子路径下也能正常跑。

**静态版能玩**：内置示例曲、本地上传、三档难度、记录与评级、主题与设置。
**静态版不能**：B 站链接提取、内置曲缺音轨时的自动补抓——这两个要靠 `tools/serve.py` 的接口。

页面会自己判断：取不到 `/api/health` 且当前不是 localhost 时进入静态模式，B 站输入框换成说明，
曲库里没有音轨的条目自动隐藏（所以两首 B 站投稿曲不会出现在 Pages 上，也不会报错）。

想把自己的歌放上 Pages：先抓成本地文件，再把条目加进 `js/app.js` 顶部的 `LIBRARY_SEED`：

```bash
python tools/bili_audio.py <BV号> --out assets/demo/mysong
```

**注意版权**——抓下来的音频能不能公开托管，取决于原作者授权。
